# Recording and replaying order flow

The host supplies market data and owns files, network connections and playback scheduling. The library supplies [`data::ReplayDriver`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html), a recording-backed feed that routes symbols through one [`ReplayClock`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayClock.html) and the same [`Sink`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.Sink.html) used by live subscriptions. Existing bar replay remains available for sources that only supply candles.

## Try a recording

On the published guide, select **Run example**. The sample writes 15 synthetic market events
to memory: one depth snapshot, one quote, 12 fills and one depth delta. It reads them back and
checks every field before loading the bytes through `ReplayDriver::load`. Trade ids, order
ids, merge ordering and nanosecond timestamps survive the round trip. Book sequence 40
starts the snapshot and 41 updates its bid size from 15 to 12 at 00:00:05 UTC.

<!-- example -->

Playback starts paused with the first recorded fill visible. Select **Step 1 second**, or **Play** and change **Speed**; **Pause**
stops advancement. **Restart** seeks inclusively to the first observation and clears later
fills and book changes before rebuilding. The chart uses one-second candles and the same
subscription sink as live data. Watch its delivered-fill count and bid size while stepping
past five seconds, then restart. No later book state should survive the seek.
With the example focused, Shift+Right steps and Shift+Down toggles play/pause; Tab leaves
the canvas. Playback pauses at the end of this finite recording.

The host calls `advance` once per frame before drawing and supplies real elapsed time,
including paused frames. This sample keeps bytes in memory rather than acquiring a feed or
writing a browser file. Replace the in-memory input with the host's recording stream in
production. [Execution coverage](order-flow.md#try-execution-coverage-and-depth-loss) shows
what happens when only part of the history is retained.

Give every [`ReplayEvent`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayEvent.html) a symbol, observation time and merge sequence. A symbol's time and sequence pair must be unique, including across trades, quotes and book messages. Equal instants across symbols share one clock and are ordered by sequence, then symbol. Payload times and symbols must agree with the envelope. Book snapshot and delta sequence numbers stay separate from the merge sequence and follow the live depth contract.

In the data adapter, write each observed event with [`RecordingWriter::write`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.RecordingWriter.html#method.write) and push it with [`ReplayEvent::push_to`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayEvent.html#method.push_to). [`RecordingWriter::capture`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.RecordingWriter.html#method.capture) also accepts an iterator of event results and propagates the first source or storage error. [`RecordingWriter::new(BufWriter::new(File::create(path)?))`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.RecordingWriter.html#method.new) writes a native file; a `Vec<u8>` works in a browser. [`finish`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.RecordingWriter.html#method.finish) flushes and propagates storage errors. Periodically record a complete book snapshot with the sequence of the last applied book event. Per-order snapshots list each price's orders in queue order. The versioned binary format preserves raw fills, optional trade, aggressor and resting order ids, sale conditions and nanosecond timestamps. Writers emit version 2, which also retains resting-order participant identifiers and placement times; readers accept version 1 without that metadata. It uses fixed little-endian fields and length-prefixed records without external dependencies. [`RecordingReader::read`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.RecordingReader.html#method.read) returns events one at a time, reports malformed/truncated input and bounds each record to 16 MiB.

For playback, call [`ReplayDriver::load(reader, instruments)`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.load) with the recording stream and one [`Instrument`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/model/struct.Instrument.html) per symbol, including its tick size. Share the driver through an `Arc` and attach it with [`Chart::set_market_replay(Some(driver.clone()))`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.Chart.html#method.set_market_replay), or use [`ChartBuilder::with_feed`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.ChartBuilder.html#method.with_feed) for a dedicated playback chart. The driver resolves symbols, rebuilds subscriptions, routes events and publishes its time to quiet symbols. Loading retains the complete recording in memory; seeking rebuilds its preceding events.

Call [`advance`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.advance) once per frame, outside egui context locks and before drawing, with real elapsed time between frames. [`set_speed(2.0)`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.set_speed) plays twice as fast and zero pauses; keep calling [`advance`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.advance) while paused to publish the shared clock. At a positive speed, advance includes events at the current time and delivers them once; [`advance(Duration::ZERO)`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.advance) consumes the starting instant without moving time. For a paused start, seek to the initial observation before connecting the chart: paused advances publish time without consuming events.

[`driver.seek(time)`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayDriver.html#method.seek) is inclusive and clears prior bars, trades, quotes, books and heatmap history before rebuilding through that instant. It replays book events from the beginning so heatmap columns before the latest snapshot remain available. New subscriptions, including interval changes, rebuild at the same position. [`Chart::set_replay_time`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.Chart.html#method.set_replay_time) uses an exclusive cutoff, one nanosecond after the driver's inclusive position. [`Chart::set_market_replay(None)`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.Chart.html#method.set_market_replay) restores the chart's original feed and retained history. Candle-only replay hides live book views; attach the driver to show recorded depth and orders.

Hosts that already manage their own sinks can still use [`ReplayClock`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayClock.html) directly. Reset every sink with [`reset_replay`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.Sink.html#method.reset_replay) before routing its [`seek`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/struct.ReplayClock.html#method.seek) output, and publish the clock time to every sink after advancing or seeking. The lower-level clock seeks book state from the latest preceding snapshot; use the driver when reconstructing heatmap history as well.

Trade, volume, delta and range bars use exactly the live aggregation rules. Volume and delta split a fill at an exact threshold while the raw tape retains it once. Unknown aggressor sides add volume and zero delta. Range bars require the instrument tick size and close at the first real execution that reaches the configured range. A jump across untraded prices can exceed the range; replay never invents trades there. A single fill producing more than 100,000 bars is rejected atomically. To reconstruct historical range bars directly, use [`aggregate_trades_with_tick_size`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/data/fn.aggregate_trades_with_tick_size.html) with the same instrument tick size.

Feeds receiving both an execution event and its separate tape print must give both the same unique trade id. The raw store then counts the fill once and completes missing order ids even when the tape print arrives first. [`Tick::aggressor_order_id`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/model/quote/struct.Tick.html#structfield.aggressor_order_id) groups known fills into an aggressive order through [`Chart::combined_trades`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.Chart.html#method.combined_trades); [`resting_order_id`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/model/quote/struct.Tick.html#structfield.resting_order_id) identifies each resting order it filled. Per-price volume always uses the raw fills. [`Chart::order_queue`](https://userfrm.github.io/egui-charts/docs/api/egui_charts/widget/struct.Chart.html#method.order_queue) exposes queue positions, largest orders and minimum-size filtered levels for host ladders and heatmaps. It returns no individual orders for aggregated-only sources.
