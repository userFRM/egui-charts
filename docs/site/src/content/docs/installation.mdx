This guide follows **main (0.3 in development)**. Use Rust 1.95 or newer and
**egui/eframe 0.37** so both dependencies share the same egui types.

| Documentation | Dependency | egui / eframe |
| --- | --- | --- |
| [main API (rustdoc)](https://userfrm.github.io/egui-charts/docs/api/egui_charts/index.html) · 0.3 in development | Git, branch `main` | `0.37` |
| [Published 0.2.0 API](https://docs.rs/egui-charts/0.2.0/egui_charts/) | `egui-charts = "0.2.0"` | `0.33.3` |

<Steps>

1. **Create your application.**

   ```sh
   cargo new my-chart
   cd my-chart
   ```

2. **Choose your dependencies.**

   Use the widget alone for a chart, the default features for a larger interface,
   or the headless engine for data processing without egui.

   <Tabs>
     <TabItem label="Chart widget">

     ```toml title="Cargo.toml"
     [dependencies]
     egui-charts = { git = "https://github.com/userFRM/egui-charts", branch = "main", default-features = false, features = ["widget"] }
     eframe = "0.37"
     chrono = "0.4"
     ```

     </TabItem>
     <TabItem label="Application UI">

     ```toml title="Cargo.toml"
     [dependencies]
     egui-charts = { git = "https://github.com/userFRM/egui-charts", branch = "main" }
     eframe = "0.37"
     chrono = "0.4"
     ```

     </TabItem>
     <TabItem label="Headless engine">

     ```toml title="Cargo.toml"
     [dependencies]
     egui-charts = { git = "https://github.com/userFRM/egui-charts", branch = "main", default-features = false }
     chrono = "0.4"
     ```

     </TabItem>
   </Tabs>

3. **Check the setup.**

   ```sh
   cargo check
   ```

   Continue with [your first chart](first-chart.mdx) to display bars in a native window.

</Steps>

<Aside title="Using a published release?">
For published **0.2.0**, use `egui-charts = "0.2.0"` and **egui/eframe 0.33.3**
with [the release documentation](https://docs.rs/egui-charts/0.2.0/egui_charts/).
The examples and feature table on this site describe main (0.3 in development).
</Aside>

## Enable what your application uses

| Feature | What it enables |
| --- | --- |
| `widget` | The egui chart, configuration and theme system |
| `studies` | Built-in studies and `IndicatorFactory`; also works headlessly |
| `alert-engine` | `services::AlertEngine`, which evaluates alerts on the bars the host feeds it; also works headlessly |
| `detectors` | `services::OrderFlowDetectors`, which finds order-flow events in the trades and depth the host feeds it; also works headlessly |
| `strategies` | `strategies::Backtest`, which runs a `strategies::Strategy` over bars and returns a `StrategyReport`; also works headlessly |
| `http` | `data::http::HttpDatafeed`, HTTP column history, symbol search and live bar refresh from your server; also works headlessly |
| `drawings` | Drawing tools, interaction, undo and persistence; enables `widget` |
| `icons` | Embedded SVG icons; enables `widget` |
| `csv` | CSV import and export for bars, strategy reports and chart data |
| `png-export` | PNG image export and image textures in SVG export; enables `widget` |
| `ui` | Toolbars, panels, dialogs, `ui_kit` and extension helpers; enables `icons`, `studies`, `drawings`, `csv` and `png-export` |
| `locales` | Localized month and weekday names and AM/PM markers |
| `timezones` | IANA zones and daylight-saving rules |
| `serde` | Serialization for `Theme` |

The defaults are `ui`, `locales`, `timezones`, `csv` and `png-export`. Omit `default-features = false`
and the explicit feature list for that setup. Add `studies` or `drawings` to the
widget-only list for those capabilities without the full application UI. Without
default features, add `csv` or `png-export` for CSV or PNG methods. With `icons`
alone, the chart installs only its embedded icon loader.

With `default-features = false` and no features, the headless engine provides
models, data contracts, scales, services and the indicator trait layer without egui.

## Native and browser hosts

The widget runs in an egui host. The [first chart](first-chart.mdx) uses eframe.
The repository's [demo](https://github.com/userFRM/egui-charts/tree/main/examples/demo)
shows an eframe WebAssembly app built with Trunk. Host windowing, event loops,
network runtimes and browser startup remain application concerns.
