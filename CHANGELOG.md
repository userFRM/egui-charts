# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to Semantic Versioning.

## [Unreleased]

### Added

- `Theme::high_contrast()` is a distinct preset: black surfaces, white text, every text colour except disabled text at 7:1 or better on panels and windows, control outlines at 4.5:1, and a light blue accent with black text. It was a copy of the dark theme.
- `Theme::with_accent` sets the accent and derives its hover and pressed shades, the black or white text on it, and the selection colours. `theme::presets()` lists the three presets by name.
- `Theme::text`, `Theme::spacing` and `Theme::radius` hold the type, spacing and corner radius scales; `apply_to_egui` takes the window and menu margins, item spacing and window and menu corner radii from them. `TextSizes::scaled` multiplies the type scale.
- The `serde` feature derives `Serialize` and `Deserialize` for `Theme`; fields missing from the input take the dark theme's values.
- `data::Datafeed`, a callback contract for market data: a feed answers instrument and history requests once through a `data::Reply` (dropping it unanswered reports `FeedError::Unanswered`) and pushes live bars, trades, status and errors through a per-subscription `data::Sink`, from any thread, runtime or browser task. Pushes coalesce on arrival into one bar per time slot, so memory follows the bars that changed rather than the update rate. Supporting types: `HistoryRequest`, `HistoryPage`, `Subscription`, `SubscriptionId`, `FeedStatus`, `FeedError`, `FeedState` and `MaybeSend` in `data`, `Instrument` and `BarClock` in `model`. `FeedError`'s messages name no source, since the host services answer with it too: `NotSupported` reads "not supported" and `Unanswered` reads "no answer". Charts do not consume it yet; `DataSource` is unchanged.
- `model::Bar` implements `PartialEq`.
- `theme::ThemeExt::active_theme`, for `egui::Context` and `egui::Ui`, returns the theme last passed to `apply_to_egui`, or the dark theme if none was, so components resolve colours while painting.
- `tokens::UiSemanticTokens` gains `panel_bg_floating_dark`, the fill of popups, menus and windows in dark themes. Struct literals of `UiSemanticTokens` must set it.
- A theme toggle in the top toolbar emits `TopToolbarAction::ThemeToggle`.
- `Indicator::update(data, from)` brings a study up to date after the bars from `from` onward changed or were appended, and `Indicator::is_incremental` reports whether a last-bar update or an append costs time independent of the series length (an earlier change still recomputes in full). `IndicatorRegistry::update_all` updates every study. Both methods have default implementations (a full `calculate`, and `false`), so existing implementors still compile. `SMA` and `EMA` update incrementally.
- Icons `CHECK`, `MINUS`, `CHEVRON_UP`, `CHEVRON_LEFT`, `CHEVRON_RIGHT`, `STAR_FILLED`, `CODE`, `USERS`, `CROWN`, `DATABASE`, `PENCIL` and `TEMPLATE` in `icons::icons`.
- `ListItemContent::interactive` lets content take its row out of pointer interaction. It defaults to `true`; a disabled `ButtonContent` returns `false`, so its row is neither highlighted nor clickable.
- `data::Sink::push_tick` also keeps each trade, with its price, size, aggressor side and time, in a bounded store for order flow, and `Datafeed::trades` pages historical trades (`TradeRequest`, `TradePage`) so order flow can be rebuilt after a reload. The default answers `FeedError::NotSupported`. History and live trades join exactly when both carry the new `Tick::id` (an exchange trade id or sequence number); without ids, trades at the boundary instant may be dropped but are never counted twice.
- Order book depth on the `Datafeed` contract: `Sink::push_depth_snapshot` and `Sink::push_depth_delta` carry a sequence number; a gap, a delta before any snapshot or an invalid update clears the book until the feed pushes a new snapshot, which is asked for once through `Datafeed::request_depth_snapshot`. A level with size 0 is removed, and a book is limited to 10,000 levels per side. Rejected updates are counted in `FeedState::rejected_depth`.
- `model::Instrument` describes the full name (`description`), exchange, instrument type, tick size, price decimals, currency, exchange time zone (`model::TimezoneId`) and trading hours (`model::Session`, `model::SessionWindow`), each unknown by default and set with a `with_` method.
- `model::Tick` implements `PartialEq`.
- `DialogFooter::danger` fills the primary action with the danger colour.
- `scales::TimezoneMode`, the time axis timezone mode, now lives next to the time formatters that use it. `config::TimezoneMode` remains as a re-export of the same type.
- `ChartState::revision` identifies the bars before the last one: it changes when one of them is corrected or bars are removed, and stays the same when bars are appended or the last bar updates.
- Per-drawing settings: `Drawing::volume_profile` (`drawings::VolumeProfileConfig`, 1 to 1,000 price rows and the value area's share of the volume, 24 rows and 70% by default), `Drawing::regression_trend` (`drawings::RegressionTrendConfig`, the band distance in standard deviations, above 0 and up to 10, 2 by default) and `Drawing::position_size` (`drawings::PositionSize`, a fixed quantity, or the quantity that loses a given amount or a percentage of an account size at the stop). `None` uses the defaults. The constructors of the two configs reject values out of bounds; a position size out of bounds reads as n/a.
- `Drawing`, `DrawingToolType`, `LineStyle`, `ArrowStyle`, `FontWeight`, `TimeframeVisibility`, `FibonacciLevel`, `FibonacciConfig`, `VolumeProfileConfig`, `RegressionTrendConfig` and `PositionSize` implement serde `Serialize` and `Deserialize`. A tool type is written as its variant name; a `Drawing` leaves out its id, points and completion state; the volume profile and regression trend settings are checked against their bounds on load; the per-timeframe visibility set is written sorted, so saving the same drawings gives the same file.
- `services::Storage`, a callback contract through which the host keeps named JSON documents for the library: it lists, loads, saves and deletes the documents of a `services::StoreKind` (`Settings` or `Drawings`) and answers through a `data::Reply`, from any thread, runtime or browser task. Nothing calls it yet. ([#198](https://github.com/userFRM/egui-charts/issues/198))
- `services::SymbolSearch`, a service the host implements to answer symbol searches from any source of instruments, separately from the feed: it takes a `services::SymbolQuery` (the typed text, optional instrument type and exchange filters, and a result limit) and answers with `Instrument`s through a `data::Reply`. `Vec<Instrument>` implements it: it matches the text against symbol and description ignoring case, applies the filters, and lists an exact symbol first, then symbols that start with the text. Nothing calls the service yet. ([#380](https://github.com/userFRM/egui-charts/issues/380))
- `services::Broker`, a callback contract for one trading account at the host's broker, real or simulated: it places and cancels orders, answering through a `data::Reply`, and pushes the account, orders, positions, executions and connection status as `services::AccountEvent`s into an `Events` stream. The trading model is in `model`: `OrderType`, `OrderRequest`, `Order`, `OrderStatus`, `Position` (signed net quantity), `Execution`, `Account` and `Capabilities` (the order types the account accepts). The library holds no balances or positions. Nothing calls the service yet. ([#216](https://github.com/userFRM/egui-charts/issues/216))
- `services::Signals`, through which a host supplies markers, levels and zones from its own analytics (`model::Signal`, `SignalShape`, `SignalId`, `Direction`) as `services::SignalEvent`s, pushed from any thread into a `services::Events` stream that holds at most 10,000 pushes between frames and ends when it lags or the chart stops listening ([#381](https://github.com/userFRM/egui-charts/issues/381)).
- `model::StrategyReport` describes a strategy run from any source: its trades, each with the net profit the host computed, its equity curve and the settings to show. `StrategyReport::performance` computes the metrics with one definition each: net, gross and average profit, profit factor, win rate, maximum drawdown in money and as a fraction of the peak, and the Sharpe and Sortino ratios, annualised by the steps per year the equity curve covers and unavailable for a curve spanning less than 13 weeks. An undefined metric is `None`, invalid trades and equity points are skipped and counted, and `StrategyReport::trades_csv` exports the valid trades. Supporting types: `StrategyTrade`, `StrategyExit`, `StrategySide` and `StrategyPerformance`.
- `services::Alerts`, through which the host keeps and evaluates price alerts: it pushes its alerts, their changes and their triggers as `services::AlertEvent`s into a `services::Events` stream, including triggers that fired while the application was closed, and saves or removes the alerts the user edits, answering through a `data::Reply`. The alert model (`model::Alert`, `AlertId`, `AlertCondition`, `AlertFrequency`, `AlertStatus`) is serialisable so a server can store and evaluate the same type. Nothing calls the service yet. ([#211](https://github.com/userFRM/egui-charts/issues/211))

### Fixed

- Logarithmic, percentage, indexed-to-100 and inverted price scales reach the screen. Candles and every other chart type, indicators, markers, drawings, the crosshair, the tooltip, the grid and the price axis render through the chart's price scale, and the series settings dialog's scale mode and invert options apply to the main price scale (`Chart::apply_series_settings`), as does the mode given to `ChartBuilder::with_right_price_scale`. A new mode returns the scale to auto-scaling and clears the zoom history. Percentage and indexed modes are relative to the first visible close; the axis, the last-price label and the crosshair label show signed percentages or index values, and box zoom fills the pane with the selected prices in every mode. A narrow logarithmic range is labelled in even price steps, and axis labels keep the same decimals at zero.
- Dragging the price axis zooms by each frame's movement around the point where the drag began, so the zoom no longer depends on how many frames the drag spans.
- The last-price line and label follow the newest bar instead of the last visible one, and are hidden while that price is off the scale.
- KAMA's efficiency ratio covers the last `period` bar-to-bar price changes, as Kaufman defines it, instead of the last `period - 1`, in both the net change and the sum of absolute changes. Migration: KAMA values from bar `period` onward differ on most series, so levels and signals tuned on the previous values need checking.
- Chandelier Exit measures its distance from Wilder's average true range, as the ATR study does, instead of a simple average of true range, and draws the short exit line as well as the long one. Migration: values after the first one change wherever the true range varies, so stops placed on the old values move.
- On Balance Volume starts at 0 on the first bar instead of at that bar's volume, which offset every value by that volume. Migration: every OBV value is lower by the first bar's volume, so thresholds set on the OBV level need the same shift; changes between bars are unaffected.
- Zig Zag draws its swings: each value between two consecutive pivots lies on the straight line joining them, instead of only the pivot bars having a value, which left nothing to draw. Bars before the first pivot and after the last stay empty, and a series without a reversal of at least the deviation has no values. Migration: pivots are the first and last bars with a value and the bars where the line changes direction, rather than the only bars with a value.
- Built-in studies clamp float parameters into a documented range at construction, NaN to the bottom of it, as they raise a length of 0 to 1: multipliers, percentages and costs to 0 or more, the Accumulation Swing limit move and the Ease of Movement and Market Facilitation divisors to `f64::EPSILON` or more, the ALMA offset to 0 to 1 and sigma to 0.001 to 100, and the Parabolic SAR factors to at most 1, with the maximum no lower than the start. `AccumulationSwingIndex::new(0.0)`, a NaN or negative band multiplier and an infinite ALMA sigma no longer turn every value into NaN or infinity.
- `FisherTransform` follows Ehlers' published construction: the normalised price is weighted by 0.33 instead of 0.66 before smoothing, the clamped value feeds the next bar, values beyond 0.99 are clamped to 0.999, and each Fisher value adds half of the previous one. Its output was off by up to several units in trends.
- Ichimoku plots Senkou Span A and B `displacement` bars after the bar they are computed on and the Chikou Span `displacement` bars before its close, instead of all on the same bar, and each line starts once it has a value instead of every line starting at the Senkou B period with 0.0 in place of missing values. Values remain one per bar, so the leading spans computed on the last `displacement` bars are not drawn. Migration: the value at bar `i` now holds the spans computed on bar `i - displacement` and the close of bar `i + displacement`; a line without a value at a bar is NaN.
- `EaseOfMovement` divides volume by 10,000 by default, as Arms defines the box ratio with volume in units of 10,000, instead of 1,000,000, which made every value 100 times too large. Migration: values with the default divisor are 100 times smaller; levels tuned on the old scale need dividing by 100, or `with_divisor(1_000_000.0)` keeps the previous scale.
- Light theme text and control outlines are readable: secondary and muted text reach at least 4.5:1 on panels and windows, unchecked checkboxes and radios, text inputs and combo boxes have a 3:1 outline, and egui's weak text uses the muted colour instead of fading by alpha. Dark theme secondary and muted text are raised to the same bar.
- `apply_to_egui` sets `error_fg_color` and `warn_fg_color` from the theme, so error text no longer uses egui's default pure red, and the status colours (success, warning, error, info) are defined per theme with at least 4.5:1 on its panels.
- Hover and pressed fills in the light theme are visible against white (1.2:1 and 1.3:1, from 1.1:1), and the accent hover and pressed shades and the danger button reds keep white text at 4.5:1 or better.
- The crate builds warning-free on current stable Rust: float literals that relied on the deprecated `f32` inference fallback are now explicitly typed.
- The documentation examples across the crate use the current crate name and module paths, and they compile and run as doctests with all features; none are skipped. The `icon_from_path!` documentation now says its path is relative to the `assets/icons/` directory of the crate that invokes the macro.
- Order line labels are shortened by rendered width with an ellipsis instead of by byte count, so labels with multi-byte characters no longer panic.
- Cloning a `CustomIndicator` or `CustomTimeFormatter` now keeps its closure instead of replacing it with an empty or default one. Migration: `CustomIndicator::new` takes the closure directly (`CustomIndicator::new(name, |bars| ...)` instead of `Box::new(...)`), and the closure must be `Sync`.
- The indicator dialog's Momentum entry creates a new `Momentum` study (the close minus the close n bars earlier, in price units) instead of Rate of Change; `Momentum` is also registered in the indicator factory.
- The export dialog no longer offers actions it cannot perform: the save path is typed into an editable field instead of a Browse button that set a fixed name, the data export text lists only the bar fields, and `ExportDialog::with_formats` limits the offered formats to those the host supports. `Exportable::copy_to_clipboard`, which discarded the image and reported success, is removed; copy a rendered `egui::ColorImage` with `egui::Context::copy_image` instead. The demo copies the chart image to the clipboard and saves PNG exports to the chosen path.
- Dashed lines are clipped to the visible area before they are dashed, so a drawing anchored far off screen no longer hangs the UI thread or exhausts memory. Every dashed line in the crate (drawings, crosshair, order lines, last-price line, session breaks, indicator pane zones) now shares this routine.
- Auto-scaling flat price or indicator data now centres the series in a range proportional to the price level instead of collapsing to a near-zero range.
- The anchored VWAP drawing computes the volume-weighted average of the typical price from its anchor bar, with bands one and two volume-weighted standard deviations away.
- The fixed range and anchored volume profiles are built from bar volume, spreading each bar's volume over its high-low range, with the point of control and a 70% value area. The anchored volume profile is placed with a single click and runs to the latest bar.
- The regression trend fits the closes between its anchors by least squares and shows the resulting R² and the Pearson correlation of the closes.
- The anchored VWAP, the volume profiles, the regression trend and Heikin-Ashi candles recompute when a bar inside their span is corrected, instead of showing values from the old bars until an anchor moved or the span grew. `ChartState::set_data` compares the new bars with the current ones to tell a correction from an append or a last-bar update, one pass over the bars per call.
- A live volume profile or regression trend no longer recomputes its whole span when the forming bar ticks or a new bar opens, or after another drawing was dragged: it adds that bar to the cached result for the bars before it (a profile only while the bar trades inside the profile's price range). At 1,000,000 bars a new bar costs about 0.002 ms instead of 20 ms for a profile, and a tick 0.001 ms instead of 5 ms for a regression trend. Heikin-Ashi candles no longer copy the whole transformed series on every frame.
- Long and short position tools have a stop of their own that moves independently of the target, so risk/reward reflects the levels set; P&L replays the bars after the entry and shows the position as closed once the stop or the target trades. Both read n/a while the stop or the target is on the wrong side of the entry.
- The forecast drawing shows the predicted change over its bar span and resolves to success once a bar reaches the target by the target bar, or to failure once the target bar has closed without that.
- The bars pattern projection draws shifted copies of the selected bars.
- The chart watermark falls back to the chart symbol and is hidden when there is none, instead of showing a placeholder.
- The OHLC header of a chart without a symbol prints prices with the same magnitude-based decimals as the legend instead of 8 decimals, and labels the last bar's volume as volume instead of 24h volume. The top toolbar's symbol pill shows no symbol instead of AAPL when none is set, the chart and series context menus leave out their alert, order, watchlist and note items until there is a symbol, and `SymbolHeader` leaves out empty info fields instead of drawing bare separators.
- Zooming the price axis in by hand stops at a span of one millionth of the price level instead of narrowing to a few nanounits, and repeated zooming out can no longer overflow the price range to infinite or NaN bounds.
- `Timeframe::duration_ms` saturates at `i64::MAX` for custom timeframes too large to represent instead of overflowing into a panic or a negative duration, and parsing a custom timeframe whose second count overflows is rejected.
- Built-in studies raise a length of 0 to 1 and accept any longer length, alone or mixed with short ones, so a zero, huge or swapped period no longer panics, exhausts memory or yields only NaN (for example `KAMA::new(0)`, `SmoothedMA::new(0)` and `MACross::new(50, 20)`).
- SMA, VWMA, LSMA, Bollinger Bands, RSI, MACD and VW-MACD return one `None` per bar instead of no values when there are fewer bars than their period.
- Stochastic no longer panics when all its periods are 1, Volume Profile Fixed Range no longer panics on a bar with a NaN price, and Rank Correlation no longer panics sorting NaN closes.
- Rainbow Oscillator keeps a running sum instead of every SMA level, so a huge level count no longer exhausts memory.
- Volume profiles refuse a row count above 10,000 and yield `None` for every bar instead of allocating that many rows for each bar.
- `to_tpo_profiles` widens the tick size to a whole number of ticks when the bars span more than 1,000 ticks and skips bars with a non-finite or inverted range, so one wide or infinite bar no longer hangs the chart or exhausts memory. Migration: `TPOProfile` has a `tick_size` field holding the row height used, which `TPOProfile::new` takes as a second argument; pass it to `tpo_count_at`, `price_levels`, `letters_at` and `classify_shape`.
- The CVD documentation states that it is estimated from bars and uses no trade or order book data.
- The keyboard focus ring uses the applied theme's `ui.focus` colour (egui's selection stroke when no theme has been applied) instead of the selection fill at reduced alpha, so it reaches 3:1 on panels and windows in every preset, and 4.5:1 in the high-contrast preset (it was 1.2:1 in light themes and 2.0 to 2.3:1 in dark ones).
- Widgets that meant the accent read the theme accent instead of the selection fill, which is pale in light themes: tab underlines, the sync button and its checkboxes, the selected drawing colour swatch, the open colour picker, the layout name input, the date picker range and Primary list item buttons. Text on an accent fill uses the theme's on-accent colour, and Danger list item buttons fill from the danger button token.
- Selected sidebar items and active chart control toggles use the selection fill and text colour (the sidebar painted accent text on an accent tint, 2.4:1 in dark themes), active tab labels use the strong text colour, descriptions on selected timeframe, chart type and template rows are no longer faded to 3.7:1, and the success status message uses the theme's success colour instead of the accent.
- Selected rows, tabs, menu items and calendar days render readable text on the selection fill instead of an empty accent bar (the selection text colour equalled the fill): white on the accent in dark themes, accent text on a pale accent fill in light themes.
- Tooltips, popups and menus have padding, a hairline border, an elevated fill, a small radius and a tight shadow; windows get padding and a border.
- `apply_to_egui` sets item spacing, window padding and menu padding from the design tokens instead of zero, so labels no longer touch their controls; toolbars, dropdown rows and stacked chart panes keep their own explicit gaps.
- Switching the theme repaints everything: the bottom toolbar, date picker, range switcher, timeframe bar, right panel tabs, symbol header, chart context menus, OHLC tooltip, replay bar and command palette resolve their colours from the active theme instead of keeping the dark theme they were built with. Fields a caller sets on the public `config` of `TimeframeToolbar`, `TimeframeBar` or `RightPanelTabs` are kept; only the fields left at their theme-derived value follow the theme.
- Custom-painted buttons (top toolbar, drawing toolbar, widget bar and the `ui_kit` buttons) draw a focus ring when they have keyboard focus.
- The dialog close button no longer draws an accent outline at rest; it looks like an icon button, so only keyboard focus draws a ring around it.
- The command palette search icon follows the theme instead of staying white, so it is visible in the light theme.
- The native demo starts on Linux: it enables wgpu's default backends instead of none.
- The README, package description, crate docs and ROADMAP state what the code does: the number of drawing tool types (counting cursor modes) and of registered indicator names, with a unit test that keeps those counts in step with the code; no unproven icon count; and no claim of magnet snapping, drawings saved by the chart or templates saved to disk, none of which works yet.
- ROADMAP ticks an item only when it works end to end: unwired widgets, scale modes the chart does not render, drawing tools with wrong geometry and indicator lines that are computed but not drawn are now unticked or carry their limits.
- The README's Rust snippets compile and run as doctests against the current API (including the `DataSource` example), and the install lines use version `0.2`.
- The `DataSource::fetch_historical` and `QuoteSource` docs describe when they are actually called: history is fetched on the UI thread, and nothing in the crate polls quote sources.
- Bar replay no longer panics when a frame is due more bars than remain, and `ReplayState::update` returns the number of bars actually advanced.
- `ListItem` allocates its row once: rows are 28 px apart with no gap, hover, pressed and selected fill the whole row, and every content type starts its icon and text 8 px inside the row. Custom `ListItemContent` implementations paint inside `ContentContext::rect` and return the row response instead of allocating space of their own. Row colours come from the active theme, with a pressed state distinct from hover and on-accent text on selected rows, and rows report their role, label and selection to accessibility tools.
- The `AutocompleteEdit` popup is exactly as wide as its input, has the popup border, aligns its suggestions with the input text and draws them in the theme's text colour.
- `FormRow` takes the height of its content instead of the remaining height of the panel, so consecutive rows and a following `FormGrid` stay visible. The label is centred on the widget's line, and the description sits below it in the theme's muted text colour.
- The `FilterWidget` search icon and clear button sit inside the field, 8 px from its edges, and the field no longer grows by a pixel when hovered or focused. Clicking the clear button now clears the query.
- The `ColorPicker` swatch is 28 px with a border that stays visible on dark colours and brightens on hover. Its popup is as wide as the swatch grid and uses the popup border, and the row below the grid shows the hex value and opacity of the selected colour.
- The compare symbols dialog draws its symbols, labels and background in the theme's colours when `CompareSymbolsConfig` leaves them at the default instead of drawing them transparent.
- The `ui_kit` buttons share one state model. Rest, hover and press are each a visible step: neutral fills move one step further from the surface, and Primary and Danger fills darken, so pressed no longer equals hover or looks paler than it; a selected `Button`, `IconButton` or `SplitButton` is drawn as Primary, filled with the accent; `enabled(false)` renders exactly like a button inside `add_enabled_ui(false)`; and a disabled Primary or Danger button is drawn as Secondary, so its faded label stays as readable as other disabled buttons, with an accent outline on a disabled Primary `Button` so a selected one still reads as selected.
- `ButtonVariant` colours follow the active theme: Primary is the theme accent with its hover and pressed shades and on-accent text, Secondary a neutral fill one step above the surface, Outlined a border in the secondary text colour, Ghost the primary text colour, and Danger the danger button reds with on-accent text.
- `Button` is as wide as its laid-out label plus 12 px on each side, instead of an estimate from the byte length, so every label gets the same padding and labels with multi-byte characters fit.
- `SplitButton` points its chevron down whether or not it is expanded.
- The `ui_kit` buttons report their role, label (the tooltip for icon-only buttons), and enabled and selected state to accessibility tools, and show their tooltip while disabled.
- The kit `Modal`, `ConfirmDialog`, `PromptDialog` and the command palette draw their dimming backdrop below their window instead of over it, so the dialog is shown at full contrast. Clicking the backdrop closes a closable modal.
- `PromptDialog` keeps the text typed into it between frames instead of resetting it to the initial value, so Enter and the submit button return what was typed.
- Saved drawings round-trip: `stored_to_drawing` restores the anchors (`chart_points`), so a restored drawing no longer disappears on the next frame, every tool type loads back, and every setting (line style, fill, font, extend, arrows, lock, visibility, per-timeframe visibility, z-order, Fibonacci levels, volume profile, regression trend and position size) is kept.
- Every drawing tool's display name parses back to that tool with `FromStr`, ignoring case; the Fibonacci extension, time zone, speed resistance fan, trend-based time and speed resistance arcs tools and the five Elliott wave tools were not parsed.
- A drawing whose tool type is unknown is skipped with the error `unknown drawing tool "Name"` instead of one listing all 95 tool types.
- `ColorType::from_hex` returns an error for input that is not six or eight hexadecimal digits, instead of panicking on a multi-byte character such as `"aÄÄb"` or accepting a sign such as `"+F+F+F"`.
- `DataValidator` reports a bar with a NaN or infinite open, high, low, close or volume as `ValidationResult::InvalidOHLC` instead of `Valid`.

### Changed

- The chart widget is behind a new default feature, `widget`, which `icons` and `ui` enable. `default-features = false` now builds the headless engine (`model`, `scales`, `data`, `studies`, `tokens`, `validation`), which depends on `ecolor` instead of egui: 24 third-party crates instead of 77. Migration: a build that sets `default-features = false` to drop the icons adds `features = ["widget"]` to keep the chart.
- `Timeframe::Custom` holds a `NonZeroU64`, so no timeframe has a zero duration: deserializing `{"Custom":0}` fails, as parsing `"0s"` already did, and the serialized form is unchanged. Migration: build a custom timeframe with `Timeframe::Custom(NonZeroU64::new(seconds)?)` or by parsing a label such as `"45s"`, and read its length with `seconds.get()` or `duration_ms()`.
- egui-charts no longer enables egui's default features. Applications built on eframe keep the default fonts (eframe enables them). Migration: an application in which no dependency enables egui's `default_fonts` feature (for example eframe with default features off and no direct egui dependency) must enable it or install its own fonts.
- The chart installs only egui_extras' SVG image loader, and only with the `icons` feature, instead of every image loader (file, HTTP, PNG, JPEG, GIF, WebP). Migration: an application that loads other images must call `egui_extras::install_image_loaders` with the egui_extras loader features it needs enabled.
- `rand`, `getrandom`, `wasm-bindgen` and `web-sys` are no longer dependencies, `egui_extras` is needed only by the `icons` feature and `thiserror` only by `ui`; with default features the library depends on 77 third-party crates instead of 140. Migration: a wasm32 application that relied on this crate enabling getrandom's `wasm_js` backend must enable it itself.
- `Theme` holds the colours and scales directly: `theme.semantic.ui` is `theme.ui` and `theme.semantic.chart` is `theme.chart`, and `theme::UiSemanticTokens` and `theme::ChartSemanticTokens` are `theme::UiColors` and `theme::ChartColors`. `UiColors` gains `focus`, the keyboard focus colour, and `danger_bg`, `danger_bg_hover`, `danger_bg_active` and `danger_text`, which kit Danger buttons and Danger list items now fill from instead of the danger button tokens. Fields that duplicated another are removed: `toolbar_bg`, `btn_bg` and `btn_bg_disabled` are `panel_bg`; `toolbar_separator` and `border_subtle` are `border`; `icon` is `text_secondary` and `icon_hover` is `text`; `icon_active`, `border_focus` and `text_link` are `accent`; `candle_up_border` and `candle_up_wick` are `candle_up`, and likewise for down; `volume_up` and `volume_down` are methods using `volume_alpha`. In the dark theme the separators and resting icons that read the removed fields are drawn in the border and secondary text colours, and hovered icons in the text colour; in the light theme the separators are the border colour and the resting icons the secondary text colour. Migration: detect these events in your application or on your server, from your own trade and order book data. `IndicatorFactory::create` returns `None` for the three names, so code that builds studies from stored names should skip unknown ones.
- The `ui::watermark` module (`Watermark`, `WatermarkManager`, `TextWatermark`, `TextWatermarkLineOptions`, `ImageWatermark`, `ImageScaleMode`, `HorizontalAlign`, `VerticalAlign` and its own `WatermarkPos`), which the chart never drew. Migration: `ui::watermark` is removed; the chart's watermark is configured through `ChartConfig` (`show_watermark`, `watermark_text`, `watermark_color`, `watermark_font_size` and `watermark_pos`, a `config::WatermarkPos`). Image watermarks, custom pixel positions and a font size, colour or weight per line have no replacement; `watermark_text` may contain `\n` for several lines in one style.
- `StoredColor`, `StoredValue`, `StoredDrawing::{tool_type, color, line_width, selected, locked, visible, properties}`, `StoredDrawing::{set_property, get_property}` and `StoredCoord::{from_screen, to_screen}` from `drawings::persistence`. Migration: read and set the settings on `StoredDrawing::drawing`; selection is not stored.
- `Deserialize` for `drawings::persistence::DrawingStorage`, which skipped the version check, the migration and per-drawing loading. Migration: load with `DrawingStorage::from_json`. To keep drawings inside your own serde state, store the `to_json` text and pass it to `from_json`.
- The `scripting` feature and module, the script editor dialog in `ui::dialogs` with its action enum, and the indicator dialog's "My scripts" category (`IndicatorCategory::MyScripts`), which listed the built-in indicators. The interpreter ignored the source argument of most `ta` functions, never reported a crossover and ran one statement per block, and the editor ran scripts on no bars and could not add one to a chart. Migration: write custom studies in Rust with `studies::CustomIndicator`; 0.2.0 keeps the module.
- The `backtest` feature and module, and the indicator dialog's "Strategies" tab (`IndicatorTab::Strategies`), which listed the built-in indicators. The backtester filled orders at the close of the signal bar, stamped trades with the wall-clock time, dropped orders larger than the cash without notice and left several metrics unset. The dialog is titled "Indicators" and the series context menu entry reads "Add indicator". Migration: run backtests in the host or on a server against the headless engine (`default-features = false`); 0.2.0 keeps the module.
